# RPMC — Raspberry Pi MSX Clone (hardware & software reference)

Complete reference for the **RPMC** (Raspberry Pi MSX Clone) slot board used by
BlueberryMSX 2.0 Plus. This document records the full hardware pin-out, the bus
protocol, the front-panel LED wiring and (verified) bit map, the build setup,
and the test procedure — so nothing has to be rediscovered.

## 1. Overview

The RPMC is a Raspberry Pi (Pi 4 / Pi 400) expansion board that turns the Pi
into a **physical MSX**:

1. **Two real MSX cartridge slots** — the emulator reads/writes real cartridges
   over the GPIO bus (no ROM dumps required).
2. **A front panel with 6 status LEDs** on a single 74HC595 shift register.
3. **A cartridge-detect switch** (SW1).
4. **The MSX master clock** (3,579,545 Hz) generated by the Pi's clock
   controller (GPCLK0, GPIO 20) and fed to the board.

The emulator is launched with both slots wired to the physical bus
(`bluemsx.sh`):

```
./bluemsx-pi /romtype1 msxbus /romtype2 msxbus $@
```

- `/romtype1 msxbus` → board **connector 1** → MSX slot-select **SLTSL1** (MSX
  slot 1) → emulator slot 0.
- `/romtype2 msxbus` → board **connector 2** → MSX slot-select **SLTSL3** (MSX
  slot 3) → emulator slot 1.

> Note: the second connector is wired to the **slot-3** select line (SLTSL3),
> not slot 2. blueMSX slot 0/1 map to the two physical connectors in order.

The `msxbus` driver is `CMSXBUS` (`Src/IoDevice/MsxBus.cpp`); the low-level
GPIO access is `msxread()`/`msxwrite()`/`msxreadio()`/`msxwriteio()`/
`msxinit()`/`msxclose()` in `MsxBusPi.c`.

## 2. Cartridge slot bus — RPMC_V5 (current, built)

Selected with `#define RPMC_V5` (`MsxBusPi.c:27`). It is a **direct GPIO** bus
(no SPI): the Pi drives address, control and data straight onto the 40-pin
header and the board latches them.

### 2.1 Pin map

Data bus D0–D7 = GPIO 0–7. Address A8–A15 = GPIO 8–15. The control signals are
decoded by the board from the same GPIO 8–15 lines (via the LE_A/LE_C/LE_D
latches), plus dedicated control pins on GPIO 16–27.

| Signal | GPIO | Notes |
|--------|------|-------|
| RD0–RD7 (D0–D7) | 0–7 | 8-bit bidirectional data bus (tri-stated by `DAT_DIR`) |
| RA8 / **SLTSL1** | 8 | Address A8 **and** slot-1 select (board connector 1) |
| RA9 / **SLTSL3** / CS12 | 9 | Address A9 **and** slot-3 select (board connector 2) / CS12 |
| RA10 / **CS1** | 10 | Address A10 **and** chip-select 1 |
| RA11 / **CS2** | 11 | Address A11 **and** chip-select 2 |
| RA12 / **RD** | 12 | Address A12 **and** read strobe |
| RA13 / **WR** | 13 | Address A13 **and** write strobe |
| RA14 / **IORQ** | 14 | Address A14 **and** I/O request |
| RA15 / **MREQ** | 15 | Address A15 **and** memory request |
| **LE_A** | 16 | Address-latch enable |
| **LE_C** | 17 | Control-latch enable |
| **LE_D** | 18 | Data-latch enable |
| **RESET** | 19 | MSX reset output (driven by the Pi) |
| **CLK** | 20 | MSX master clock (GPCLK0, ALT5, 3,579,545 Hz) |
| **DAT_DIR** | 21 | Data-bus direction: 0 = Pi drives (write), 1 = board drives (read) |
| (595 SRCLK) | 22 | 74HC595 shift clock — see §4 |
| (595 RCLK) | 23 | 74HC595 latch (STROBE) — see §4 |
| **INT** | 24 | Interrupt (cartridge → Pi) |
| **WAIT** | 25 | Wait (cartridge → Pi) |
| (595 SER) / BUSDIR | 26 | 74HC595 serial data — see §4 (`BUSDIR_PIN` is defined but unused in the V5 path) |
| **SW1** | 27 | Cartridge-detect switch (input, active-low) |

The board reconstructs the full 16-bit address, the control byte and the data
byte from the shared bus by sampling it at the LE_A / LE_C / LE_D latch
moments.

### 2.2 Bus protocol (per access)

All three phases use `GPIO_SET`/`GPIO_CLR` on the memory-mapped GPIO registers.

**SetAddress(addr)** — `MsxBusPi.c:216`:
1. De-assert `LE_C`, clear the low 16 lines and `DAT_DIR`.
2. Drive `addr` onto the bus, pulse `LE_A` (latch address) and `LE_D`.
3. Drive the control flags (`MSX_CONTROLS`), latch with `LE_C`.
4. De-assert `LE_D` and clear the data lines.

**SetData(...) / GetData(...)** — strobe the access and honour WAIT:
- Write (`SetData`): drive the byte, assert `WR`, poll `WAIT` until the
  cartridge de-asserts it, then de-assert `WR`.
- Read (`GetData`): set `DAT_DIR` (board drives the bus), assert `RD`, poll
  `WAIT`, sample the byte from GPIO 0–7, de-assert `RD`.

`WAIT` (GPIO 25) is polled with `while(!(GPIO & MSX_WAIT));` — the cartridge
can stretch the cycle. `checkInt()` (`MsxBusPi.c:310`) polls `INT` (GPIO 24)
and calls `boardSetInt(0x10000)` when the cartridge requests an interrupt.

**Chip-select decode** (`msxread`, `MsxBusPi.c:264`):
```c
cs1 = (addr & 0xc000) == 0x4000 ? MSX_CS1 : 0;   // 0x4000–0x7FFF → CS1
cs2 = (addr & 0xc000) == 0x8000 ? MSX_CS2 : 0;   // 0x8000–0xBFFF → CS2
```

### 2.3 Power-up sequence — `setup_io()`

1. Map `/dev/mem`, get the GPIO base (`bcm2835_regbase(BCM2835_REGBASE_GPIO)`)
   and the clock base (`bcm2835_regbase(BCM2835_REGBASE_CLK)`).
2. Enable GPCLK0 → 3,579,545 Hz (see §3).
3. Configure pull-ups on the data lines (0–7) and SW1 (27).
4. Drive the control lines, latch, then **pulse MSX RESET** (GPIO 19) low for a
   short delay and back high to reset the cartridge.

## 3. MSX master clock (GPCLK0)

The board needs the MSX T1 master clock, **3,579,545 Hz** (colour-burst
derived), on GPIO 20 (GPCLK0, ALT5). It is synthesised from the 19.2 MHz core
clock using the BCM2835 clock controller:

```
divi = 19200000 / 3579545 = 5
divf = fractional part → 1490 / 4096
19200000 / (5 + 1490/4096) ≈ 3,579,545 Hz
```

Register writes (`MsxBusPi.c:356–367`, `gclk_base = 0x7e101000`):

```c
GP_CLK0_CTL = 0x5A000000 | 1;                 // 0x7e101070: GPCLK0 off
while (GP_CLK0_CTL & 0x80);                   // wait for BUSY (bit7) low
GP_CLK0_DIV = 0x5A000000 | (5 << 12) | 1490;  // 0x7e101074: integer=5, frac=1490/4096
GP_CLK0_CTL = 0x5A000010 | 1;                 // 0x7e101070: GPCLK0 on (source select)
```

`0x5A000000` is the standard BCM2835 register-write **passkey** required for
clock-controller writes. Result: 3,579,545 Hz on GPIO 20 → board `CLK`.

## 4. Front-panel LEDs — 74HC595 shift register

One **74HC595** (8-bit shift register) drives the 6 front-panel LEDs. Serial
data is shifted in **LSB-first** (bit 0 first) and latched on RCLK.

### 4.1 74HC595 wiring

| 74HC595 pin | Function | GPIO |
|-------------|----------|------|
| SRCLK (11) | Shift clock | **22** |
| RCLK (12) | Latch / STROBE | **23** |
| SER (14) | Serial data | **26** |

(74HC595 OE and CE are tied low = always enabled; Q7' is unused.)

### 4.2 Verified LED bit map

Determined by sweeping each bit and observing the panel (see §7). **6 LEDs,
MSB-first in the table:**

| Bit | Value | LED | Meaning |
|-----|-------|-----|---------|
| 7 | 0x80 | **PWR** | Power — on while the emulator runs |
| 6 | 0x40 | **SLT2** | Slot 2 (board connector 2) cartridge activity |
| 5 | 0x20 | **SLT1** | Slot 1 (board connector 1) cartridge activity |
| 4 | 0x10 | **I/O** | Cartridge I/O activity (SLT1 **or** SLT2) |
| 3 | 0x08 | **HAN** | Kana (Japanese) mode |
| 2 | 0x04 | **CAPS** | Caps Lock |
| 1 | 0x02 | — | **Not connected** |
| 0 | 0x01 | — | **Not connected** |

**The board has 6 LEDs. It has no FDD or TURBO LEDs** — this corrects the old
assumption carried in the legacy `frontled()` status builder (see §5.1).

### 4.3 Old vs verified map

| Bit | Legacy `frontled()` map (dead code) | Verified board |
|-----|--------------------------------------|----------------|
| 7 | PWR | PWR |
| 6 | SLT2 | SLT2 |
| 5 | SLT1 | SLT1 |
| 4 | FDD2 | **I/O** |
| 3 | HAN | HAN |
| 2 | CAPS | CAPS |
| 1 | FDD1 | **not connected** |
| 0 | TURBO | **not connected** |

## 5. Software

### 5.1 Two LED drivers — which one is live

Both drivers shift the **same** 74HC595 (GPIO 22/23/26), LSB-first:

- **`frontled(byte)`** — `MsxBusPi.c:744` (forward-declared at `:364`). Uses
  the raw `GPIO_SET`/`GPIO_CLR` memory map (no bcm2835), no per-bit delay,
  guarded by a `pthread_mutex`. **Effectively dead code** in the current
  build:
  - The only live call is `frontled(0x0)` inside `msxinit()` (`MsxBusPi.c:722`,
    call at `:731`) — a **no-op** (the `static oldbyte` starts at 0, so
    `oldbyte != byte` is false and nothing is shifted).
  - The other call sites — `Emulator.c:852–870` (the per-frame "status byte"
    builder) and `PiMain.c:511` (`frontled(0)` on exit) — are wrapped in
    `#ifdef RPMC_FRONTLED`, which the **Makefile does not define**, so they are
    compiled out.
  - The `Emulator.c` status builder uses the **old** map from §4.3 and also
    contains a bug: line 865 calls `ledSetSlot2Busy()` (a setter) where it
    should call `ledGetSlot2Busy()` (a getter).

- **`gpioShiftLeds(byte)`** — `Src/Pi/PiGpio.c`, under `RASPI_GPIO`, built on
  **bcm2835** (WiringPi was dropped — it does not build on aarch64). This is the
  **live** driver. It shifts with a 10 µs half-period and only re-shifts when
  the byte changes.

### 5.2 LED state sources

- **PWR** — set in `gpioInit()` (POWER bit), cleared in `gpioShutdown()`.
  Called from `PiMain.c:277` (start) and `PiMain.c:499` (exit).
- **SLT1 / SLT2** — "slot busy" flags. `CMSXBUS::readMemory()`
  (`MsxBus.cpp:106–146`, under `RASPI_GPIO`) sets the busy flag for the slot
  being read, throttled to roughly once per 100 reads
  (`if (time++ > 100)`), so the LED lights while a slot is actively accessed
  without strobing.
- **I/O** — `gpioUpdateLeds()` (`PiGpio.c:47`) computes `IO = SLT1 || SLT2`
  each update.
- **HAN / CAPS** — from the keyboard state via `ledGetKana()` /
  `ledGetCapslock()` in `Src/IoDevice/Led.c`.
- **Per-frame refresh** — `PiMain.c:149` `updateLeds()` →
  `gpioUpdateLeds()`, invoked on `EVENT_UPDATE_DISPLAY` (`PiMain.c:162`, call
  at `:172`). The
  74HC595 (GPIO 22/23/26) uses a **disjoint** set of pins from the V5 cartridge
  bus (GPIO 0–21, 24, 25, 27), so LED shifts never contend with cartridge
  accesses even in the multithreaded (Z80-on-its-own-thread) configuration.

### 5.3 Cartridge detect (SW1)

GPIO 27, active-low. `msx_pack_check()` returns "pack present" when the line is
low. The call in `Src/Emulator/CommandLine.c:363` is currently **commented out**
(auto power-off on pack removal is disabled).

## 6. Build

- **`Makefile`** (Pi, `bluemsx-pi` target):
  - `COMMON_FLAGS` includes **`-DRASPI_GPIO`** (line 40) → enables the Pi GPIO
    code path (`PiGpio.c`, the slot-busy block in `MsxBus.cpp`).
  - `LIBS` includes **`-lbcm2835`** (line 44). WiringPi is **fully removed** —
    no references remain.
  - `INCLUDE` adds `bcm2835-1.60/src/` (line 103). `BCM_LIBDIR=/opt/vc/lib`
    (line 23).
  - `RPMC_FRONTLED` is **not** defined anywhere → the legacy `frontled()`
    status path is compiled out (see §5.1).
- **bcm2835 versions in the repo:** `bcm2835-1.56/`, `bcm2835-1.60/` (headers
  the Makefile compiles against), `bcm2835-1.68/` (the version the README build
  steps build + install). The build links the **installed** static
  `libbcm2835.a` (`/usr/local/lib`) with `bcm2835.h` in `/usr/local/include`.
  As committed, it builds and runs as-is.
- **Committed binary** `bluemsx-pi`: **aarch64** ELF, dynamically linked only
  against system libraries (SDL2, udev, drm, gbm, GLESv2, EGL, pulse, X11, …).
  **bcm2835 is statically linked** (it does not appear in `ldd`), so end users
  on 64-bit Raspberry Pi OS run the committed binary **without building any
  GPIO library**.
- **Privilege:** the slot bus and the 74HC595 both access `/dev/mem` directly.
  Run as root, or add the user to the `gpio` group. If `bcm2835_init()` fails,
  `PiGpio.c` prints "slot LEDs disabled" and the emulator continues without
  LEDs.

## 7. Test procedure — LED bit-map sweep

To (re)verify the 74HC595 bit map, use the standalone sweep program
`/tmp/sweep_leds.c` on the Pi (a small bcm2835 program, not part of the repo):

1. Stop the emulator (so it isn't also driving the 74HC595).
2. Compile and run **as root** from the console:
   ```
   sudo gcc -o /tmp/sweep_leds /tmp/sweep_leds.c -lbcm2835
   sudo /tmp/sweep_leds
   ```
3. It shifts `0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80` in turn, pausing
   ~2 s on each. Watch the front panel and note which LED lights for each value.
4. The result should match the verified map in §4.2.

## 8. Troubleshooting

- **No LEDs at all** — confirm the binary was built with `-DRASPI_GPIO`, that
  you're running with `/dev/mem` access (root / `gpio` group), and that GPIO
  22/23/26 are the 74HC595 SRCLK/RCLK/SER on this board revision. The PWR bit
  is set at `gpioInit()`, so PWR should light as soon as the emulator starts.
- **A slot LED never lights** — slot-busy is only set while that slot is
  *read* (and only ~once per 100 reads). A game that lives entirely in the slot
  0 BIOS and never touches a cartridge in that slot won't light it.
- **Wrong LED lighting for an event** — re-run the sweep (§7); the board may be
  a different revision with a different 74HC595 bit order.
- **No sound** — Moonsound / MSX-Music are stubbed and silent on aarch64 (see
  `CHANGES.md` §1).
- **Need to debug the GPIO bus?** — the emulator logs through spdlog and is
  silent by default. Enable the full startup trail with
  `settings.logLevel=debug` in `bluemsx.ini` or
  `BLUEMSX_LOG_LEVEL=debug` (see `README.md` "Logging" / `CHANGES.md`
  §v2.0.4). The bus init messages ("MSX BUS initialized", GPCLK state, slot
  mounts) all appear at `info`/`debug`.
- **Silent at boot even though a cartridge is inserted** — that's expected: a
  healthy boot prints nothing at the default level. Use `info`/`debug` or the
  `rom_tester` utility to see the slot activity.

## 10. Hardware Revision Note (V2019 vs V5)

A review of the 2019-01-01 schematic mapping reveals a discrepancy in the RESET line:
- **2019 Schematic**: RESET is driven via RC24 (GPIO 24 / Pin 18).
- **Current Software (V5)**: RESET is driven via RC19 (GPIO 19 / Pin 35).

All other primary bus signals (S-Bus, Latch Enable, and Wait) remain consistent between the versions. Users of the 2019 hardware may need to update `MsxBusPi.c` to use `RESET_PIN 24` for proper reset functionality.
